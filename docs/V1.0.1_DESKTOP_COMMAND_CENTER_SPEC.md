## 1. Executive Objective

The primary objective of RYU AI **v1.0.1** is **NOT** to invent new cognitive algorithms or alter the frozen runtime architecture.

The objective is:
> **Expose the capabilities that already exist and are verified in RYU AI through the Desktop Command Center.**

In **v1.0.0**, RYU established and verified the core runtime, deterministic space isolation, pulse bus durability, CAS execution planning, capability admission control, cryptographic approval gates, sandboxed workers, node profiles, memory adaptation, and LLM synthesis.
However, the user experience in the Desktop UI remained constrained to a single transient session in the `"default"` space, without dialogue rehydration, artifact inspection, file ingestion, or live HTML sandboxed rendering.

**v1.0.1** bridges this gap:
* **v1.0.0:** *"RYU can do it."*
* **v1.0.1:** *"The user can actually see, control, inspect, and use what RYU can already do."*

Under no circumstances will architectural authority boundaries be bypassed or weakened to accommodate UI convenience.

## 2. Baseline & Audit Reconciliation

This specification incorporates the findings of the **RYU Interaction & Multimodal Capability Audit** (`docs/audits/RYU_INTERACTION_MULTIMODAL_CAPABILITY_AUDIT.md`):

1. **Text-First Agentic Architecture:** The core runtime is 100% verified across 649 automated tests. Text reasoning, code generation, task planning, and tool dispatch are fully operational.
2. **Voice Runtime Non-Goal:** `core/voice/__init__.py` is a Phase 0 stub (`NotImplementedError`). STT, TTS, microphone streaming, audio playback, and barge-in are explicitly **OUT OF SCOPE** for v1.0.1.
3. **Binary Document Parsing Non-Goal:** Binary parsing for PDF, DOCX, XLSX, and PPTX is not implemented in the backend. v1.0.1 supports text-based files (`.txt`, `.md`, `.json`, `.py`, `.js`, `.ts`, `.html`, `.css`).
4. **Artifact Disconnection:** The backend `FileWorker` generates `Artifact` records with SHA-256 digests (`workers/contract.py`), but the Channel Daemon lacks query endpoints and the Desktop UI lacks an Artifact Explorer.
5. **Session Transience:** The Desktop UI currently maintains conversation history only in React `useState`, causing loss of chat history upon window reload or restart. The underlying PostgreSQL pulse store already preserves the full history; it merely requires exposure.

## 4. Functional Requirements

### FR-01: Conversation History Rehydration
* The system shall persist and rehydrate dialogue turns (user prompt, assistant response, goal ID, and execution status) per Space.
* Upon desktop application launch or space switching, the UI shall fetch historical turns from the Channel Daemon and display them chronologically.
* Chat messages must reflect actual runtime pulse causality (`goal.defined`, `agent.prompt.request`, `agent.prompt.response`).

### FR-02: Space Lifecycle & Switching
* The Desktop TopBar shall display an active Space Switcher dropdown populated dynamically from the Channel Daemon.
* Users shall be able to create a new Space via a modal ("Create Space") providing Space ID, Name, and optional attention budget.
* Switching spaces shall cleanly switch SSE event streams, clear/rehydrate chat messages, update the Attention Gauge, and refresh tasks and audit logs.

### FR-03: Sandboxed HTML & Code Preview
* When assistant responses or artifacts contain HTML/JS/CSS code blocks, the UI shall provide a tabbed selector: `[Code | Preview]`.
* The preview shall render the markup inside an isolated `<iframe>` configured strictly with `sandbox="allow-scripts"`.
* The iframe must **NOT** include `allow-same-origin`, preventing script execution from accessing Tauri IPC (`window.__TAURI__`), parent DOM, cookies, local storage, or loopback network tokens.

### FR-04: Space Artifact Explorer
* The Desktop Right Drawer shall include an **Artifacts** tab.
* The tab shall list all artifacts generated within the active Space, displaying artifact name, MIME type, size in bytes, SHA-256 hash, and generation timestamp.
* Users shall be able to inspect artifact content inline or copy/download the artifact.

### FR-05: Sandboxed File Ingress
* The Desktop chat interface shall provide a file attachment button and drag-and-drop zone for text/code files (`.txt`, `.md`, `.json`, `.py`, `.js`, `.ts`, `.html`, `.css`, `.yaml`, `.csv`).
* The frontend shall enforce a 2MB maximum file size limit.
* The backend Channel Daemon shall sanitize the filename, verify text integrity, write the content into the designated Space sandbox directory, and emit a `file.uploaded` / `pulse` event to the bus.
* Uploaded files are automatically made available to the Space context as tainted input data (preserving TAINT-001/TAINT-005 invariants).

### FR-06: Read-Only System Visibility (Nodes & Memory)
* The Desktop Right Drawer shall offer read-only visibility into connected node runtimes (`NodeRegistry`) and space memory reflections (`SpaceMemoryManager`).
* This surface must remain strictly observational, providing zero direct mutation authority.

## 5. Architectural Invariants & Authority Boundaries

1. **The Desktop UI is a Channel Client (Zero Independent Authority):**
   * The desktop application (`apps/ryu-desktop`) must never connect directly to PostgreSQL or Redis.
   * The desktop application must never perform local OS file writes outside its designated asset cache.
   * All operations are relayed via HTTP/SSE through the loopback Channel Daemon (`http://127.0.0.1:8420`) authenticated with `Bearer <token>`.
2. **Deterministic Core Independence (Core Boundary Rule):**
   * No files in `core/` may import from `channels/`, `apps/`, or cognitive layers.
   * All new daemon endpoints and adapters reside strictly in `channels/daemon/`.
3. **SCCA Law 1 (Everything Happens Inside a Space):**
   * All history, artifacts, files, tasks, and memory queries are strictly partitioned by `space_id`.
   * Cross-space leakage is strictly prohibited.
4. **SCCA Law 3 (Components Communicate Through Pulses):**
   * Space creation, file uploads, and plan executions emit authoritative typed pulses onto the `PulseBus`.
5. **Cryptographic Human Approval Invariant:**
   * Human approvals continue to be signed client-side using WebCrypto HMAC-SHA256 (`token-hmac-v1`). No endpoint permits bypassing cryptographic verification.

## 6. Channel Daemon API Specifications

All endpoints require `Authorization: Bearer <token>` unless explicitly noted.

### 6.1 Space Management
* `GET /api/v1/spaces`
  * Returns: `{"spaces": [{"space_id": str, "name": str, "status": "active", "created_at": float}]}`
* `POST /api/v1/spaces`
  * Request Body: `{"space_id": str, "name": str, "attention_limit": int, "owner_id": str}`
  * Logic: Validates space ID format `^[a-zA-Z0-9_-]+$`; instantiates `SpaceKernel`; records in space registry; emits `space.created` pulse.
  * Returns: `{"success": true, "space": {"space_id": str, "name": str}}` (Status 201).

### 6.2 Conversation History
* `GET /api/v1/spaces/{space_id}/history`
  * Query Params: `?limit=100`
  * Logic: Queries `pulse_store.read_by_space(space_id)`. Reconstructs prompt-response dialogue turns by correlating `goal.defined`, `command_id`, and synthesizer pulses.
  * Returns:
    ```json
    {
      "space_id": "default",
      "turns": [
        {
          "id": "turn-1727400000",
          "user_prompt": "Build a landing page",
          "assistant_response": "Here is the HTML code...",
          "timestamp": 1727400000,
          "goal_id": "goal-123",
          "status": "completed"
        }
      ]
    }
    ```

### 6.3 Artifact Registry
* `GET /api/v1/spaces/{space_id}/artifacts`
  * Returns:
    ```json
    {
      "space_id": "default",
      "artifacts": [
        {
          "artifact_id": "art-001",
          "name": "index.html",
          "path": "spaces/default/artifacts/index.html",
          "mime_type": "text/html",
          "size_bytes": 1420,
          "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
          "created_at": 1727400050
        }
      ]
    }
    ```
* `GET /api/v1/spaces/{space_id}/artifacts/{artifact_id}/content`
  * Logic: Verifies artifact belongs to `space_id`; reads file content from sandboxed artifact directory; prevents path traversal.
  * Returns: `{"artifact_id": str, "name": str, "mime_type": str, "content": str}`

### 6.4 Sandboxed File Ingress
* `POST /api/v1/spaces/{space_id}/files`
  * Request Body: `{"filename": str, "content": str, "mime_type": str}`
  * Validation:
    * Filename sanitized via strict basename regex (no `/`, `\`, `..`, null bytes).
    * Maximum size: 2,097,152 bytes (2 MB).
    * Allowed extensions: `.txt`, `.md`, `.json`, `.py`, `.js`, `.ts`, `.html`, `.css`, `.yaml`, `.yml`, `.csv`.
    * Disallowed: executable binaries, hidden files, `.env`, `.git`.
  * Logic: Writes content to `spaces/{space_id}/ingress/{filename}`; registers as Space input artifact; emits `file.uploaded` pulse with `taint=True`.
  * Returns: `{"success": true, "filename": str, "bytes_written": int, "sha256": str}` (Status 201).

### 6.5 System Visibility (Nodes & Memory)
* `GET /api/v1/nodes`
  * Returns: `{"nodes": [{"node_id": str, "platform": str, "status": str, "capabilities": [str]}]}`
* `GET /api/v1/spaces/{space_id}/memory`
  * Returns: `{"space_id": str, "insights": [str], "reflections": [dict], "experience_count": int}`

## 7. Security Model & Sandbox Hardening

```text
┌─────────────────────────────────────────────────────────────┐
│                 TAURI DESKTOP APPLICATION                   │
│                                                             │
│  ┌──────────────────────┐        ┌───────────────────────┐  │
│  │   Parent App Window  │        │   Sandboxed Iframe    │  │
│  │   (Tauri IPC, DOM,   │        │   sandbox="           │  │
│  │    Tokens, State)    │  ────X │    allow-scripts"     │  │
│  └──────────────────────┘        │   (NO same-origin)    │  │
│                                  │   (NO Tauri IPC)      │  │
│                                  │   (NO token access)   │  │
│                                  └───────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                               │ Loopback HTTP (8420)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 LOCAL CHANNEL DAEMON                        │
│  - Bearer Token Auth Verification                           │
│  - Filename Sanitization & Path Traversal Guards            │
│  - Taint Propagation (Uploaded files marked taint=True)     │
└─────────────────────────────────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 DETERMINISTIC RYU RUNTIME                   │
│  - SpaceKernel Isolation                                    │
│  - Filesystem Sandbox & Capacity Quotas                     │
└─────────────────────────────────────────────────────────────┘
```

1. **HTML Preview Sandbox Invariant:**
   * `<iframe sandbox="allow-scripts" srcdoc={sanitizedHtml} />`
   * By omitting `allow-same-origin`, the iframe is treated as an opaque origin. It cannot read the host window's `localStorage`, access parent cookies, call Tauri IPC invoke methods, or make authenticated loopback requests with stolen bearer tokens.
2. **File Ingress Path Traversal Defense:**
   * Filenames are strictly normalized using `os.path.basename` and sanitized via `re.sub(r"[^a-zA-Z0-9_.-]", "_", name)`.
   * Destination path must be resolved and verified to be strictly within `spaces/{space_id}/ingress/`.
3. **Taint Tracking Integrity:**
   * All ingress files are treated as untrusted user inputs. The daemon emits a pulse tagging the resource with `taint: true`. Any worker consuming this file inherits taint under SCCA Law 1 and TAINT-001.

## 8. Persistence & State Lifecycle

1. **Space State:**
   * Spaces are instantiated via `SpaceKernel` and registered in the Daemon's `space_registry`.
   * Space configuration and lifecycle pulses are persisted durably in PostgreSQL via `DurablePulseBus`.
2. **History Reconstruction:**
   * Conversation history is derived deterministically from the pulse stream. The daemon inspects `goal.defined` pulses (user inputs) and corresponding completion/response pulses to rehydrate turns.
3. **Artifact Storage:**
   * Artifact records are stored in a space-scoped in-memory / JSON-backed catalog, pointing to files residing in `spaces/{space_id}/artifacts/`.

## 10. Failure Taxonomy & Error Handling

All daemon error responses conform to the standard schema:
```json
{
  "error": "Human readable error description",
  "status_code": 400,
  "error_class": "VALIDATION_FAILED"
}
```

* `SPACE_NOT_FOUND` (404): Specified space ID does not exist in registry.
* `SPACE_ALREADY_EXISTS` (409): Attempting to create a space with an existing ID.
* `FILE_TOO_LARGE` (413): Uploaded file exceeds 2 MB limit.
* `UNSUPPORTED_MEDIA_TYPE` (415): Uploaded file has a disallowed extension or contains binary null bytes.
* `PATH_TRAVERSAL_DETECTED` (400): Filename attempts directory traversal (`../`).
* `DAEMON_UNAUTHORIZED` (401): Missing or invalid Bearer token.

## 13. Explicit Non-Goals & Boundaries

To preserve architectural integrity, the following are strictly **PROHIBITED** from v1.0.1:
1. Speech-to-Text (STT) and microphone audio capture.
2. Text-to-Speech (TTS) and voice synthesis.
3. WebRTC audio/video calling or streaming.
4. Binary document parsing (PDF, DOCX, XLSX, PPTX, OCR).
5. Direct database (Postgres/Redis) connections from the Desktop frontend.
6. Weakening iframe sandbox permissions (e.g. adding `allow-same-origin`).
7. Modifying deterministic SCCA core modules to accommodate UI requests.
