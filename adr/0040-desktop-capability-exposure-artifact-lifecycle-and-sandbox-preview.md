# ADR-0040: Desktop Capability Exposure, Artifact Lifecycle, and Sandboxed Preview

## Context
In RYU AI v1.0.0, the core runtime, Space-Centric Cognitive Architecture (SCCA), deterministic space isolation, durable pulse bus, CAS execution planning, capability admission control, cryptographic approval gates, sandboxed workers, node profiles, and memory adaptation were fully established and verified across 649 tests.

However, the desktop user experience in `apps/ryu-desktop` (Tauri v2 + React 18) was constrained:
1. The UI was locked to a hardcoded `"default"` space with no space creation or switching controls.
2. Conversation history was maintained solely in React component state, causing all chat history to disappear upon application reload or restart.
3. Code blocks generated by prompts or workers were displayed only as raw text with copy buttons, with no safe mechanism to preview HTML/JS/CSS.
4. Artifacts generated by `FileWorker` (`workers/contract.py`) had no persistent query interface or explorer UI.
5. Users had no mechanism to upload or attach files into space context.

## Problem
1. How do we expose these verified capabilities in the Desktop Command Center without violating the fundamental invariant that the Desktop UI is strictly an untrusted Channel / Client with zero independent authority?
2. How do we render generated HTML/JS artifacts without exposing the desktop application's Tauri IPC bridge, host filesystem, or local daemon bearer tokens to Cross-Site Scripting (XSS) or sandbox escapes?
3. How do we support file ingress into space context without compromising filesystem sandbox isolation or violating taint tracking invariants?

## Decision

### 1. Loopback Channel Daemon as the Sole Exposure Boundary
The Desktop Command Center remains strictly a client interface. It never connects directly to PostgreSQL or Redis, and never writes directly to runtime paths on the host filesystem. All operations are mediated by the authenticated loopback Channel Daemon (`http://127.0.0.1:8420`) via `Bearer <token>`.

### 2. Space Lifecycle & History Rehydration via Daemon
- **Space Lifecycle:** The Channel Daemon exposes `POST /api/v1/spaces` to instantiate a `SpaceKernel` and register it in `space_registry`. The Desktop TopBar consumes `GET /api/v1/spaces` to provide dynamic space switching and creation.
- **History Rehydration:** The Channel Daemon exposes `GET /api/v1/spaces/{space_id}/history`. Dialogue turns (prompt, response, goal ID, and execution status) are rehydrated deterministically by querying the underlying `pulse_store.read_by_space(space_id)`.

### 3. Zero-Privilege HTML Iframe Sandbox
To support live preview of HTML/JS/CSS code blocks and artifacts:
- Previews are rendered strictly inside an `<iframe sandbox="allow-scripts" srcdoc={markup} />`.
- The sandbox attribute **MUST NOT** include `allow-same-origin`.
- **Security Boundary:** Omitting `allow-same-origin` forces the iframe into a unique opaque origin. Scripts running inside the iframe cannot access `window.parent`, `window.__TAURI__`, `localStorage`, cookies, or make authenticated loopback fetch requests with the user's bearer token.

### 4. Space-Scoped Artifact Catalog & Explorer
- The Channel Daemon exposes `GET /api/v1/spaces/{space_id}/artifacts` and `GET /api/v1/spaces/{space_id}/artifacts/{id}/content`.
- Artifacts are indexed per space with SHA-256 integrity digests, MIME types, and timestamps.
- The Desktop Right Drawer provides a dedicated **Artifacts** tab allowing users to inspect, preview, and download space artifacts.

### 5. Sandboxed File Ingress with Taint Preservation
- The Channel Daemon exposes `POST /api/v1/spaces/{space_id}/files`.
- Ingress is restricted to validated text/code formats (`.txt`, `.md`, `.json`, `.py`, `.js`, `.ts`, `.html`, `.css`, `.yaml`, `.csv`) with a maximum payload limit of 2 MB.
- Filenames are strictly sanitized to prevent directory traversal (`../`).
- Files are saved in `spaces/{space_id}/ingress/`.
- Ingress emits a pulse tagged with `taint: true`, ensuring all downstream workers consuming the file enforce taint tracking under SCCA Law 1 and TAINT-001.

## Invariants
```text
Desktop UI = Channel / Client (Zero Independent Authority)
Daemon = Authenticated Loopback Adapter (Bearer Token Auth)
HTML Sandbox = sandbox="allow-scripts" WITHOUT allow-same-origin
Ingress Files = Sandboxed Path + Size Bound (<= 2MB) + Tainted (taint=True)
Core Independence = core/ imports nothing from channels/ or apps/
```

## Consequences
- The Desktop Command Center becomes a full, persistent, multi-space interface for RYU AI.
- Conversation history survives restarts and space transitions without needing a duplicate frontend database.
- Safe, interactive rendering of generated HTML applications without exposing desktop credentials or Tauri IPC.
- Complete auditability and taint safety for user-ingested files.
